# 20260803 Docker 构建前端外置打包实施计划

## 计划概述
- **目标**：调整 `deploy/docker/build-image.sh` 与 `Dockerfile`，将前端构建从镜像内搬到宿主机执行，产物打包为单个 `tar.gz` 复制进镜像，简化前端阶段依赖并加快镜像构建。
- **范围**：仅修改 `Dockerfile`、`deploy/docker/build-image.sh`、`.dockerignore`、相关说明文档；保持后端多阶段构建、运行配置、Compose 编排与产物布局完全不变。
- **不包含**：不改后端构建、不调整镜像运行参数、不引入 Node 运行时到最终镜像、不改变 SPA 资源访问路径。
- **预期成果**：`deploy/docker/build-image.sh` 负责构建并打包前端；`Dockerfile` 仅 `COPY` 单个 tar.gz 并解压到 Nginx 目录；多架构构建脚本路径不变。
- **成功标准**：宿主机执行 `bash deploy/docker/build-image.sh` 后能在当前架构产出 `aigbooks:latest`，最终镜像内 `/usr/share/nginx/html/index.html` 存在且非空；后端启动行为保持一致。

## 需求背景
- **原始需求**：`deploy/docker/build-image.sh` 与 `Dockerfile` 避免在镜像中构建前端，在外部构建好，打包成 `.tar.gz`，复制进去。
- **澄清结果**：`build-image.sh` 自带前端构建与打包步骤；产物命名 `frontend-dist.tar.gz`（位于仓库根，供 Dockerfile 复制）；Dockerfile 移除 `frontend-builder` 阶段，使用 `COPY + tar -xzf` 解压。
- **业务价值**：消除镜像内 Node 依赖、减小构建上下文传输、缩短冷构建时间、避免重复安装 `node_modules`。
- **成功标准**：
  1. `bash deploy/docker/build-image.sh` 在已有 Node 22 + pnpm 9 环境中可一键完成前端构建、打包与镜像构建。
  2. 镜像内 `/usr/share/nginx/html/index.html` 存在；`/usr/share/nginx/html/models`、`ort-wasm`、`zxing`、`covers` 等 OCR 静态资源随之落地。
  3. 后端 `uv` 阶段、Nginx 配置、运行用户、入口脚本、Compose 服务均不发生行为变化。

## 影响范围
- **修改文件**：
  - `Dockerfile`（删除 `frontend-builder` 阶段、`COPY` 改用 `tar.gz` 并解压）
  - `deploy/docker/build-image.sh`（新增前端构建 + 打包 + 清理逻辑）
  - `.dockerignore`（白名单允许 `frontend-dist.tar.gz`）
  - `deploy/docker/README.md`（补充宿主机前置依赖 Node 22 / pnpm 9 说明）
- **新增文件**：
  - `frontend-dist.tar.gz`（构建时生成，`.gitignore` 排除）
- **不涉及**：数据库、API、后端代码、Compose 服务、运行用户/卷/端口。
- **第三方依赖**：无新增；仍沿用 `pnpm` 锁文件与 `uv` 锁文件。

## 设计原则遵循
- **构建可重复性**：宿主机必须安装 Node 22（与锁文件兼容）；`pnpm install --frozen-lockfile` 与 `pnpm build` 保留现有语义。
- **构建上下文精简**：`.dockerignore` 显式保留 `frontend-dist.tar.gz`（白名单 `!` 语法），避免被 `**/dist` 等规则误排除。
- **镜像分层合理**：在 `runtime` 阶段仅做单文件 `COPY` 与解压，避免目录级 COPY 触发的额外校验开销。
- **失败可观测**：脚本在打包前对 `frontend/dist` 做存在性检查，缺失时给出明确错误并退出非零。
- **YAGNI**：不在最终镜像保留任何 Node 产物；不引入 buildx、不引入 build-arg 控制开关。

- 代码调整清单
  | 操作 | 代码块/模块 | 说明 |
  |------|-------------|------|
  | 新增 | `build-image.sh::build_frontend` | 步骤：1) `cd frontend`；2) `pnpm install --frozen-lockfile`；3) `pnpm build`；4) `cd ..`；5) `tar -czf frontend-dist.tar.gz -C frontend dist`；6) 输出大小/校验。 |
  | 新增 | `build-image.sh::cleanup_frontend_bundle` | Docker 构建成功后删除 `frontend-dist.tar.gz`，失败时保留以便排错。 |
  | 修改 | `build-image.sh::main` | 在 `docker build` 之前调用 `build_frontend`；注册 `trap EXIT` 实现清理。 |
  | 修改 | `Dockerfile::runtime` | 删除 `frontend-builder` 阶段与 `COPY --from=frontend-builder /src/frontend/dist /usr/share/nginx/html`；新增 `COPY frontend-dist.tar.gz /tmp/...` 与 `tar -xzf` 解压命令及 `test -f index.html` 自检。 |

- 测试用例调整清单
  | 操作 | 用例ID | 场景 | 输入/步骤 | 预期结果 | 说明 |
  |------|--------|------|----------|---------|------|
  | 新增 | TC-1.1 | 宿主机执行 `bash deploy/docker/build-image.sh` | 仓库根目录、Node 22 + pnpm 9 + Docker | 产物镜像 `aigbooks:latest` 构建成功，仓库根出现 `frontend-dist.tar.gz`（构建完成后被清理） | 验证脚本编排 |
  | 新增 | TC-1.2 | Dockerfile `runtime` 阶段解压 | 手动 `docker run --rm aigbooks:latest ls /usr/share/nginx/html/index.html` | 退出码 0，文件存在 | 验证解压自检 |
  | 新增 | TC-1.3 | 缺失前端构建产物 | 在 `frontend/dist` 不存在时调用 `build_frontend` | 脚本以非零退出并打印明确错误 | 防止空打包 |
  | 新增 | TC-1.4 | `.dockerignore` 误排除 tar.gz | 镜像构建过程中 `docker build` 不应报源文件缺失 | 构建成功 | 验证白名单 |

- 核心设计要点
  - 压缩包命名固定为 `frontend-dist.tar.gz`（位于仓库根），避免 `.dockerignore` 中 `**/dist` 误伤。
  - `tar -czf` 顺序先 cd 再打包，确保包内仅含 `dist/` 目录结构，解压时直接落到 `/usr/share/nginx/html`。
  - `Dockerfile` 用 `COPY` + `tar` 而非 `ADD`，遵循最佳实践并保留构建缓存粒度。
  - `test -f /usr/share/nginx/html/index.html` 作为产物自检，避免 dist 缺失导致的静默失败。
  - 清理使用 `trap 'rm -f "$FRONTEND_BUNDLE"' EXIT`，既覆盖成功也覆盖失败分支。
