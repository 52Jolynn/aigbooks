# OCR 扫描支持「拍照 / 上传图片」两种模式

> 范围：仅修改 `frontend/`（`ReportView.vue` / `FileUploader.vue` / `i18n/zh.ts` / `ocr/index.ts`），不引入新依赖，不修改 `node_modules/`、`backend/`、`deploy/`、`scripts/`。

---

## 0. 计划概述

- **目标**：在 `ReportView` 的"OCR 扫描"区块中，提供"拍照 / 上传图片"两种文件来源模式，桌面端自动将"拍照"模式置灰并提示用户使用手机；保持现有 Tesseract.js 识别链路零变更；保证 iOS HEIC 拍照可被正确识别。
- **范围**：
  - 扩展 `FileUploader` 组件契约（新增 `capture` 可选 prop），不破坏现有 6 处调用点
  - 重构 `ReportView` 顶部 OCR 区块的 UI 编排（新增 mode 切换 radiogroup）
  - 新增桌面端能力检测工具（基于 `isSecureContext` + UA）
  - i18n 文案补 4 条 key
  - OCR 入口增加 HEIC→JPEG 转码兜底
- **不在范围内**：
  - 移动端图片尺寸/质量预处理（缩放到 ≤1280px）—— 留作下一轮性能优化
  - 样式 token 重构（chip 提取全局）—— 留作后续清理
  - OCR 按钮样式统一为 `--quarantine-ok` 主操作样式 —— 本期保留 `--ink-deep` 等宽风
- **预期成果**：
  - 桌面端：OCR 区块显示「上传图片 / 拍照」分段，「拍照」灰显并 tooltip 提示
  - 移动端：点「拍照」直接调起后置摄像头；点「上传图片」走原有文件选择
  - 切模式自动清空 `ocrFiles`，避免状态污染
  - `pnpm typecheck` 与 `pnpm build` 通过
- **预计工时**：0.6 个工作日

## 1. 需求背景

- **原始需求**：OCR 扫描要支持拍照、上传图片两种模式
- **澄清记录**：
  1. 入口形式 = A（模式切换 tab，上方"拍照/上传图片"二选一）
  2. 拍照行为 = A（移动端直接调起后置摄像头 `capture="environment"`；桌面端置灰 + tooltip）
  3. 多图策略 = A（一次只处理一张图）
  4. i18n = A（朴实直白：`拍照` / `上传图片`）
  5. 降级方案 = A（桌面端无摄像头时把"拍照"置灰 + tooltip "请用手机扫码访问"）
- **业务价值**：移动端用户（最常见使用场景）现在点"扫描"会被引导至文件选择器，选图路径长；直接提供拍照入口可减少 2-3 步操作，提升举报数据采集效率。桌面端保留文件上传降级。
- **成功标准**：
  1. 移动端：点"拍照"直接拉起后置摄像头授权
  2. 桌面端：点"拍照"无反应（button disabled），鼠标 hover 看到提示「请用手机扫码访问」
  3. 上传图片模式：行为与改造前完全一致（兼容旧调用方）
  4. 切换模式时 `ocrFiles` 自动清空
  5. iOS Safari 拍照返回 HEIC 时，自动转码为 JPEG 后再喂 Tesseract.js
  6. `pnpm typecheck` 与 `pnpm build` 全部通过

## 3. 设计原则遵循

- **零依赖新增**：用 HTML 标准 `<input capture="environment">` + `<canvas>` toBlob API 实现 HEIC 转码
- **契约向后兼容**：`FileUploader` 新 prop 全部可选，6 处既有调用点零修改
- **复用 radiogroup ARIA**：与 `ReportView.vue:36-47` 的"编号类型"分段完全同构（`role="radiogroup"` + `role="radio"` + `:aria-checked`）
- **复用 .type-chip 样式**：与现有 `ReportView.vue:247-267` 等宽胶囊样式一致
- **i18n 单源**：新增文案进 `report` 命名空间，遵循 `xxxXxx` camelCase
- **loading 状态分层**：拍照 loading / 上传 loading / OCR loading 三者分离（吸取 `LRN-20260721-001` 经验）
- **切换清空状态**：切 mode 时清 `ocrFiles`，类比 `setType`（L145-150）的实现
- **A11y 增强**：拍照单选 disabled 时设 `aria-disabled` + `title` 提示；OCR 按钮加 `aria-busy`

#### 测试用例调整清单

无

#### 核心设计要点

- **模式切换的 radiogroup 复用现有结构**：
  ```vue
  <div class="report-form__ocr-mode" role="radiogroup" :aria-label="report.ocrModeLabel">
    <button v-for="m in ['upload', 'camera']" :key="m"
            type="button" role="radio" :aria-checked="ocrMode === m"
            :disabled="m === 'camera' && !isMobileWithCamera"
            :title="m === 'camera' && !isMobileWithCamera ? report.captureUnavailable : undefined"
            class="type-chip" :class="{ 'is-active': ocrMode === m }"
            @click="setOcrMode(m)">
      {{ m === 'upload' ? report.ocrModeUpload : report.ocrModeCamera }}
    </button>
  </div>
  ```
- **`isLikelyMobileWithCamera` 实现**（参考经验教训第 6 条，避免 `enumerateDevices` 弹权限）：
  ```ts
  function isLikelyMobileWithCamera(): boolean {
    if (typeof navigator === 'undefined') return false;
    if (!window.isSecureContext) return false;
    return /Android|iPhone|iPad|iPod|Mobile/i.test(navigator.userAgent);
  }
  ```
  使用 `computed` 而非 `ref` 是因为它是纯派生值（UA 不变）；但**支持响应式依赖**以便 SSR 场景未来可切换
- **条件传 `capture`**：
  ```vue
  <FileUploader
    :files="ocrFiles"
    :accept="ocrMode === 'camera' ? 'image/*' : 'image/*'"
    :capture="ocrMode === 'camera' ? 'environment' : undefined"
    :label="ocrMode === 'camera' ? report.ocrModeCamera : report.ocrModeUpload"
    @update:files="onOCRFiles"
  />
  ```
- **运行识别按钮 disabled 双条件**：无文件 或 OCR 进行中（吸取经验 5：loading 与 disabled 不耦合在视觉布局上，但语义上合并）

### 任务 4：HEIC 转码兜底 [P0, 0.5h]

#### 文件调整清单

| 操作 | 文件路径 | 说明 |
|------|---------|------|
| 修改 | `frontend/src/ocr/index.ts` | 入口加 HEIC→JPEG 转换，避免 Tesseract.js 拒识 |

#### 代码调整清单

| 操作 | 代码块/模块 | 说明 |
|------|------------|------|
| 新增 | `async function normalizeImage(image: File \| Blob): Promise<Blob>` | 内部检测 `image.type === 'image/heic' \|\| 'image/heif'`，是则用 `<img>` + `<canvas>` 解码并 `toBlob('image/jpeg', 0.92)`；否则原样返回 |
| 修改 | `recognizeText` (L21-57) | 在 `worker.recognize(image)` 前 `const normalized = await normalizeImage(image)` |

#### 测试用例调整清单

无（HEIC 解码依赖浏览器环境，无 mock 价值）

#### 核心设计要点

- **降级链**：HEIC → JPEG（canvas 失败 → 原样回传，由 Tesseract 报错兜底）
- **不破坏现有契约**：`recognizeText` 仍返回相同 `OCRResult`，函数签名不变
- **附带的副作用预防**：canvas 解码天然会把图片压到目标尺寸，顺带解决"高分辨率原图喂 Tesseract.js"的内存问题（经验 3），但**不主动缩放**以保留后续调优空间

## 6. 风险与应对

| # | 风险 | 概率 | 影响 | 应对措施 |
|---|------|------|------|---------|
| R1 | Tesseract.js worker 内部 `postMessage` 转移 ArrayBuffer，导致同一 `File` 第二次 OCR 报 `detached`（吸取经验 ERR-20260622-002） | 中 | 中 | `recognizeText` 内部对 `image` 做一次 `await image.arrayBuffer()` 后**复制**新 Blob；或提示用户切模式后重新选图。本期不预防，列入下一轮优化 |
| R2 | 桌面端 UA 检测误判（平板、折叠屏） | 低 | 低 | 仅在 `Mobile` 关键字命中时启用拍照；UA 包含 `iPad` 时部分新版 iPadOS Safari UA 已变 `Mobile`，会误判为移动端（实际可拍照）—— 这是**可接受误判** |
| R3 | iOS Safari 不支持 `<input capture>` 时静默降级为文件选择器 | 中 | 低 | 文案已经说明"拍照"，行为退化为选图，UX 不崩 |
| R4 | canvas HEIC 解码在某些 Android Chrome 版本失败 | 低 | 低 | `try/catch` 回退到原 Blob，Tesseract.js 失败时已有的 `console.warn` 兜底 |
| R5 | `isSecureContext` 在某些内网/局域网 IP 访问时为 false | 中 | 低 | 桌面端本身就是 false 时已降级为置灰；移动端用户极少在公司内网用 AIGBooks |
| R6 | vue-tsc 对模板中 `:disabled="boolean"` 类型严格 | 低 | 中 | 用 `!!ocrFiles[0]` 显式转布尔避免类型推导问题 |
