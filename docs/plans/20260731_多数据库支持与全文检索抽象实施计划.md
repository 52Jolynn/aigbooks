# 20260731-多数据库支持与全文检索抽象实施计划

## 计划概述

- **目标**：aigbooks 后端实现 PostgreSQL / SQLite / MySQL 三套数据库完整等价支持，含 UPSERT、IP 字段、全文检索（含中文分词），运行期通过 `AIGBOOKS_DATABASE_URL` 一行切换。
- **范围**：
  - 抽象层：方言无关的类型、UPSERT、全文检索接口
  - 模型改造：`INET`/`TSVECTOR` 退化为方言无关类型；`ip` 改 `String(45)`
  - 全文检索：PG `websearch_to_tsquery`、SQLite FTS5（jieba 自定义分词）、MySQL `FULLTEXT ... WITH PARSER ngram`
  - 迁移：Alembic 同文件按 `dialect.name` 分支，三库一套迁移链
  - 测试：三方言 fixture + 集成测试矩阵
- **预期成果**：
  1. `AIGBOOKS_DATABASE_URL=sqlite+aiosqlite:///./var/aigbooks.db` 单文件开发可用
  2. `AIGBOOKS_DATABASE_URL=mysql+asyncmy://...` 一键切换，搜索可用
  3. 中英文混合搜索在三个后端结果一致（差异化的能力在文档中显式标注）
- **预计工时**：3–5 天

## 需求背景

- **原始需求**：用户要求数据库增加 sqlite 支持，要求支持多数据库切换（sqlite / pg / mysql），但未使用 pg 时，要如何解决全文检索问题？
- **澄清记录**（来自会话问答）：
  | 维度 | 决策 |
  |------|------|
  | FTS 方案 | **A. 方言后端抽象**（PG websearch_to_tsquery / SQLite FTS5 / MySQL FULLTEXT） |
  | 中文分词 | **需要 jieba**（应用层 jieba + SQLite FTS5 自定义分词 + MySQL ngram parser） |
  | MySQL 范围 | **三套完整实现**（runtime 依赖 + Alembic 迁移 + 集成测试） |
  | 迁移策略 | **同文件按 dialect 分支**（`op.get_bind().dialect.name` 判断） |
  | `tsv_*` 列 | **保留映射**，用 TypeDecorator：PG 下 TSVECTOR、SQLite/MySQL 下 nullable Text |
  | IP 字段 | **字符串化 String(45)**（兼容 IPv4/IPv6，去掉 INET） |
  | 中文分词实现 | **jieba 0.42+**（应用层 + SQLite 自定义 tokenizer，MySQL 走 ngram） |
- **业务价值**：
  - 开发演示可零依赖启动（SQLite 单文件）
  - 生产可按需选择 PG/MySQL（自有/云服务差异）
  - 中文搜索在三套数据库都可用，搜索结果不会因数据库选型发生质变
- **成功标准**：
  1. 三套数据库下，`alembic upgrade head` 全部成功，建表完整
  2. 三套数据库下，`POST /api/reports`（Book UPSERT + Report 插入）200 通过
  3. 三套数据库下，`GET /api/search?q=<中文>` 返回合理结果（PG 用 simple 配置 + LIKE 回退；SQLite FTS5 用 jieba；MySQL FULLTEXT 用 ngram）
  4. 三套数据库下，`POST /api/reports/{id}/vote` 重复投票行为一致（同方向 → 计 1 票；反方向 → 切换）
  5. 中文混合搜索（"AI 换脸 视频"类）在三套数据库召回结果一致（结果数量允许差异，但召回到的核心条目应相同）

### 数据库变更
是。**新建 Alembic 迁移 `002_multidb.py`**：
- PG：等价于 `001_init.py`（保持 GIN + 触发器）
- SQLite：建主表 + FTS5 虚拟表 `books_fts(title, author)`、`reports_fts(description)` + 同步触发器
- MySQL：建主表 + `FULLTEXT INDEX books_ft_idx (title, author)` / `reports_ft_idx (description) WITH PARSER ngram` + 应用层同步触发器（用 SQLAlchemy event listener 而非 DB 触发器，因 MySQL 触发器无法直接写 FULLTEXT）

### 第三方依赖
是。新增 runtime 依赖：
- `aiosqlite>=0.20`（SQLite async driver；当前已在 dev，需要移到 runtime）
- `asyncmy>=0.2.9`（MySQL async driver，PyMySQL 异步版本，psycopg2-asyncmy 兼容层）
- `jieba>=0.42`（中文分词）

## 设计原则遵循

基于代码调查，新代码将遵循以下项目设计原则：

1. **绝对导入**（`from app.xxx import ...`），禁止相对导入
2. **`from __future__ import annotations`** 全部新文件保持
3. **类型注解**用 PEP 604 `str | None` + `list[...]`，与既有风格一致
4. **`async def` 全异步**，数据库/路由/服务层统一
5. **`HTTPException(detail={"code": int, "msg": str})`** 错误抛出风格不变
6. **Settings 单例 + pydantic-settings** 不另起配置框架
7. **schema 与 ORM 解耦**（`schemas.py` 不 import `models.py`），新搜索后端亦如此
8. **`lazy="raise"`** relationship 风格保留
9. **`cascade="all, delete-orphan"` + FK `ON DELETE CASCADE`** 保留
10. **ruff `line-length=100`**、`**target-version=py310**、select=`E,F,I,N,W,UP,B,C4,SIM`；新文件 B008 仅在 router 忽略
11. **DRY**：将 `_SPECIAL_CHARS` 与 `sanitize_query` 抽离到 `app/utils/text.py`，被搜索模块复用
12. **KISS / YAGNI**：不引入 ORM 框架级的方言抽象，只做"够用"的 4 个抽象点

## 风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| SQLite 异步多连接 `SQLITE_BUSY`（任务 1/8） | 高 | 高 | `busy_timeout=5000`、`journal_mode=WAL`、SQLite 测试用 `StaticPool` 单连接 |
| jieba 词典锁死锁 alembic 迁移（任务 4/6） | 中 | 中 | Alembic 进程**不预热 jieba**（迁移 DDL 不需要分词）；仅 FastAPI worker 预热 |
| MySQL `ft_min_token_size=2` 未配置导致中文单字召回失败（任务 6） | 高 | 中 | 迁移中注释提示 DBA 设置；或文档化 `SET GLOBAL innodb_ft_min_token_size=2;` |
| SQLite FTS5 自定义分词器与 async 引擎不兼容（任务 4） | 中 | 高 | 通过 `engine.sync_engine` 注册（aiosqlite 暴露 sync API）；`create_function` 在 `connect` 事件中执行 |
| Alembic SQLite batch mode 重命名失败（任务 6） | 中 | 中 | `render_as_batch=True` 仅 SQLite 分支开启；所有 op 包在 `with op.batch_alter_table()` 内 |
| MySQL `WITH PARSER ngram` 不可改（任务 6） | 低 | 高 | 文档化**不可后期调整 parser**；未来如要切换 zhparser，需新建列 + 数据迁移 |
| TypeDecorator bind/result 不对称（任务 2） | 中 | 高 | `cache_ok=True` + 单测覆盖 PG/SQLite/MySQL 对称；code review 强校验 |
| PG `text("interval '...'")` 方言陷阱（限流改造） | 低 | 中 | 任务 7 中已改为 Python 端计算 cutoff，绕开方言 |
| 三方言 SQL 语法差异（`now()`/`datetime()`/`current_timestamp`） | 低 | 中 | 统一用 `func.now()`（三方言都支持） |
| 测试矩阵复杂度爆炸（任务 8） | 高 | 中 | CI 三 Job 并行；本地默认只跑 sqlite；PG/MySQL 跑集成测试需要 service container |
