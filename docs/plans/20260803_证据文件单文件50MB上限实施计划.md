# 证据文件单文件上限调整为 50MB 实施计划

## 计划概述

- **目标**：将每个证据文件的上传上限由 20MB 调整为 50MB，封面和 OCR 图片仍保持 20MB。
- **范围**：前端校验与提示、后端证据文件校验、部署请求限制、测试和设计文档。
- **预期成果**：单个证据文件不超过 50MB 可提交；超过 50MB 在前后端均被拒绝；多文件只逐个校验，不设置业务总量上限。
- **预计工时**：0.5 天。

## 需求背景

- **确认规则**：每个证据文件最大 50MB；多文件不设置业务总量上限。
- 封面与 OCR 上传继续使用 FileUploader 默认 20MB。
- Nginx 的请求级上限无法表达“仅限制单文件且总量不限”，因此需设置足够高的安全请求上限，并由 FastAPI 对每个 evidence 执行 50MB 校验。

## 影响范围

- `frontend/src/views/ReportView.vue`
- `frontend/src/components/FileUploader.vue` 或其测试（仅复用现有 `maxSize`，预计无需改组件）
- `backend/app/config.py`
- `backend/app/services/storage.py`
- `backend/.env.example`
- `backend/tests/conftest.py`
- 后端上传大小测试
- `deploy/nginx-aigbooks.conf`
- `deploy/README.md`
- `docs/plans/2026-07-29-aigbooks-design.md`

无数据库和 API 字段变更。

## 任务分解

### 任务 1：同步设计文档

- 明确封面 20MB、证据单文件 50MB、多文件逐个校验。
- 明确代理层只设置请求级安全上限，不替代业务校验。

### 任务 2：清理与拆分全局上传配置

- 保留 `max_upload_size=20MB` 供封面使用。
- 新增 `max_evidence_size=50MB`，避免扩大封面上限。
- 更新环境变量示例。

### 任务 3：实现前后端 50MB 校验

- ReportView 为证据 FileUploader 显式传入 50MB。
- `save_evidence` 使用 `max_evidence_size`，每个文件独立校验。
- 超限返回 413 和清晰文案。
- 评估并适当提高前端请求超时，避免 50MB 文件在慢速网络下被 30 秒超时中断。

### 任务 4：调整部署请求限制

- 提高 Nginx `client_max_body_size` 至部署安全上限，使多个合法证据文件可通过代理层。
- 说明 Nginx 仍是单次 HTTP 请求总量保护，业务层不限制多文件合计大小。

### 任务 5：测试与验证

- 前端：验证 evidence 50MB 边界，cover/OCR 仍 20MB。
- 后端：验证 50MB 可接受、超过 50MB 返回 413、多个文件分别小于 50MB 时通过业务校验。
- 执行前后端现有测试、前端 typecheck/build。
- 清理无用和重复常量，更新计划状态为已完成。

## 验收标准

| 场景 | 预期 |
|---|---|
| 单个证据文件恰好 50MB | 允许 |
| 单个证据文件大于 50MB | 前端拒绝；绕过前端时后端返回 413 |
| 多个证据文件均小于等于 50MB | 业务校验允许，不计算总和 |
| 封面或 OCR 图片大于 20MB | 仍按原规则拒绝 |
| 慢速网络上传 50MB | 不因现有 30 秒前端超时过早失败 |

## 风险与应对

| 风险 | 应对 |
|---|---|
| Nginx 只能限制请求总量 | 设置足够高的部署安全上限，业务层逐文件校验 |
| 多文件总量过大消耗磁盘和带宽 | 保留代理层请求级安全保护，并记录部署配置说明 |
| FastAPI 读取文件后才检查大小 | 本次保持现有存储模式；后续如并发压力上升再改流式计数 |
| 50MB 在慢网超过 axios 30 秒 | 调整举报上传请求超时或该接口单独超时 |
