## 1. 需求背景

- **原始需求**：做一个"关于"页，阐述本站设立的初衷、意图。
- **澄清记录**：
  1. **文案来源 = 我代笔**（基于 `README.md`、`docs/plans/2026-07-29-aigbooks-design.md`、现有 i18n 文案基线撰写）
  2. **路径与导航 = `/about` + 加入 Masthead 顶部主导航**（不加入 Colophon 页脚）
  3. **内容范围 = 初衷 + 原则 + 引用条款**（"如何参与"由本站"提交举报"页面承载，本页不重复）
  4. **视觉风格 = 完全沿用"临床样本台 / 图书检疫所"**（不引入新的视觉范式或字体）
- **业务价值**：让新访客在 30 秒内理解"本站是什么、不是什么、由谁维护、为什么可信"，降低匿名社区类项目的"我能否信任你"门槛。
- **成功标准**：
  1. `/about` 路由可访问，无 console 错误；Masthead 导航的"关于"在 `/about` 时 `.is-active` 状态正确。
  2. 内容三段完整呈现：**初衷**（为何设立 / 服务于谁）、**原则**（4–6 条对仗短句）、**引用条款**（免责 / 隐私 / 不构成事实认定 / 引用 disclaimer 与 colophon）。
  3. 全部 § 编号顺延为 01/02/03/04/05；`vue-tsc --noEmit` / `pnpm test` / `vite build` 全部通过。
  4. 视觉与现有页（HomeView / SearchView / ReportView / IdentifierDetailView）一致：`<main class="ledger">` + 单一 `SectionHeader` + 复用全局 `.disclaimer` / `.book-detail__warning` 容器。
  5. 文案语气贴合现有"审慎 / 不自我表彰 / 不下业务结论"基线（参考 `disclaimer.body` / `colophon.line3`）。

## 3. 设计原则遵循

基于代码调查报告，新代码将遵循以下项目设计原则：

1. **§ 编号顺延**：`sectionNum = '§ 05 —'`，不重排 § 01–04。
2. **单一 i18n 信息源**：所有固定文案（含标题、段落、原则条目、条款标题与正文、meta 文案）全部进 `src/i18n/zh.ts` 的 `about` 命名空间，不在 `.vue` 内写硬编码字符串。
3. **全局样式优先**：复用 `.ledger` / `.section-head` / `.disclaimer` / `.book-detail__warning` / `.featured__lede`；scoped style 仅用于"原则清单"列表项的微调（如 `::before` 装饰符）。
4. **lazy import 路由**：与现有 4 路由完全同型。
5. **is-active 用 `route.name` 字符串比对**：与现有 3 个 RouterLink 同型。
6. **零 `useRecentStore` 副作用**：纯静态展示，不读 store、不写 store，规避 watch 回路风险。
7. **不动 `prefers-reduced-motion` / 焦点环 / skip-link**：沿用全局兜底规则。
8. **文案语气**："郑重 + 而非"对仗的短句（参考 B1 调研建议），与 `colophon` / `disclaimer` 同基线。
