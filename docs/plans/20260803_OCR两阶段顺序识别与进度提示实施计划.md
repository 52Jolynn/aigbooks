# OCR 两阶段顺序识别与进度提示实施计划

## 计划概述

- **目标**：在前端 OCR 工具中保留上传图片、拍照、实时条码扫描三种模式；上传或确认照片后自动依次执行条码识别与文字 OCR，并在界面实时展示当前处理步骤。
- **范围**：调整前端识别编排、结果合并、页面状态与中文文案；同步产品设计文档。实时条码模式保持只识别 ISBN/ISSN，不追加 OCR。
- **预期成果**：条码识别结束后立即回填有效 ISBN/ISSN，再进入 OCR；OCR 完成后立即补充 ISBN/ISSN、书名、作者；条码失败不阻断；条码与 OCR 编号冲突时条码优先；用户可明确看到每一步的状态。
- **预计工时**：1 天。

## 需求背景

- **原始需求**：OCR 扫描支持上传图片、拍照识别两种模式；识别拆分为条形码识别和文字/ICP 数据识别两步，并明确提示当前处理步骤。
- **澄清记录**：
  - 两步自动连续执行。
  - 第二步仅使用本地文字 OCR，不调用 ICP 外部服务。
  - OCR 同时提取 ISBN/ISSN、书名、作者等字段。
  - 条码未识别到唯一标识时仍继续 OCR。
  - 保留实时条码扫描第三种模式，该模式只扫描条码，不继续 OCR。
  - 条码和 OCR 编号冲突时以条码为准。
  - 上传图片或确认照片后自动开始，完成后保留再次识别能力。
  - 每个阶段得到有效结果后立即填充表单，不等待整个识别流程结束。
- **业务价值**：降低手工录入成本，避免长耗时 OCR 期间用户无法判断系统状态，并通过两种识别方式互补提高字段回填率。
- **成功标准**：
  - 上传和拍照均严格按“条码 → OCR”顺序执行。
  - 条码成功、未命中或异常均会进入 OCR 阶段。
  - 条码阶段得到有效 ISBN/ISSN 后立即回填表单，OCR 阶段无需等待即可继续运行。
  - OCR 阶段得到有效 ISBN/ISSN、书名、作者后立即补充表单。
  - UI 同时显示两个步骤，并明确标识待执行、处理中、成功、未命中或失败。
  - 实时条码模式行为不变。

## 设计原则遵循

- 上传和拍照复用统一识别编排，不在采集组件中复制业务逻辑。
- 阶段状态与最终结果分离，避免单一 `source/error` 丢失过程信息。
- 条码阶段失败采用降级策略，不阻断 OCR。
- 保持现有 Vue Composition API、局部响应式状态、纯 CSS 和中文文案单一来源。
- 不修改 `node_modules/`，不引入浏览器自动化测试。

| 修改 | 结果合并 | 条码编号优先；OCR 补充缺失编号、书名和作者；OCR 无结果不清空有效字段 |

#### 合并规则

1. 条码有效编号优先于 OCR 编号。
2. 条码无编号时使用 OCR 的有效 ISBN/ISSN。
3. 书名和作者由 OCR 提供，仅填充非空结果。
4. 条码成功但 OCR 失败时保留条码结果。
5. 条码失败但 OCR 成功时以 OCR 结果完成回填。
6. OCR 阶段必须被调用；模糊度保护属于 OCR 阶段内部的合法结束状态。

## 风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|---|---|---|---|
| OCR 初始化和推理耗时较长 | 高 | 中 | 清晰展示当前步骤，识别期间避免重复提交 |
| 用户快速更换图片导致旧结果覆盖 | 中 | 高 | 使用运行序号使过期结果失效 |
| 条码与 OCR 编号冲突 | 中 | 中 | 固定条码优先，并保留 OCR 对书名作者的补充 |
| OCR 无有效字段但没有错误码 | 中 | 中 | 编排层依据结果字段判断 noMatch |
| OCR 失败清除已识别条码 | 低 | 高 | 阶段结果独立存储，最终合并保留条码结果 |
| 现有工作区存在未提交 PaddleOCR 改动 | 高 | 高 | 基于当前文件增量修改，不回滚、不 checkout、不覆盖已有改动 |
