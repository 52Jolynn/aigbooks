# 20260802-日志框架调研与按天滚动实施报告

## 1. 调研结论

候选三方案对比（权威来源：Python 官方文档、Loguru API、structlog 26.x）：

| 框架 | 滚动策略 | 接管 stdlib | 新依赖 | 推荐场景 |
|------|---------|------------|-------|---------|
| **`logging` 标准库** | `TimedRotatingFileHandler(when='midnight', interval=1)` | 自动 | 无 | 中小项目 / 零依赖偏好 |
| **loguru** | `rotation="00:00"`/`retention="14 days"`/`compression="gz"` 内置 | 需 `InterceptHandler` 桥接（~15 行） | `loguru` | API 极简诉求 |
| **structlog** | 复用 stdlib handler | `structlog.stdlib` 内置 | `structlog` | 结构化 JSON / 日志聚合 |

**用户选定方案**：**stdlib + TimedRotatingFileHandler**（最小侵入、零新依赖、接管 uvicorn/sqlalchemy 全自动）。

## 3. 核心实现

### 3.1 配置（`app/logging_config.py`）

- 格式：`%(asctime)s | %(levelname)-7s | %(name)s | %(filename)s:%(lineno)d | %(message)s`
- 两个 handler：
  - `TimedRotatingFileHandler(filename=log_dir/aigbooks.log, when='midnight', interval=1, backupCount=14, encoding='utf-8')`，suffix `"%Y-%m-%d"`
  - `StreamHandler(stream=sys.stderr)`（开发期保留；生产可关 `log_to_console=False`）
- 清空 `uvicorn`/`uvicorn.error`/`uvicorn.access`/`sqlalchemy.engine` 自带 handler，置 `propagate=True` 让其走 root
- `logging.captureWarnings(True)` 把 `warnings.warn` 也吸进日志

### 3.2 文件布局

```
backend/var/logs/
├── aigbooks.log                       # 当天活动日志（tail -f 永远跟最新）
├── aigbooks.log.2026-08-01            # 昨天的（保留）
├── aigbooks.log.2026-07-31            # 前天的（保留）
└── ...                                # 14 天前的自动删除
```

## 4. 使用示例

```python

from app.config import get_settings
from app.logging_config import setup_logging

setup_logging(get_settings())  # 已在 create_app() 内自动调用

logger.info("业务事件")                 # → stderr + var/logs/aigbooks.log
```

## 5. 已知未修 Bug（与本次任务无关）

`GET /api/books/{isbn}` 在 SQLite 单 ISBN + 多 Report 场景返回 500：

```
pydantic_core._pydantic_core.ValidationError:
  reports.0.book
    'Report.book' is not available due to lazy='raise'
```

根因：`app/routers/books.py:51-59` 的 `selectinload(Book.reports).selectinload(Report.evidences)` 缺 `selectinload(Report.book)`。

## 6. 后续可选

1. 多 worker 下共享日志：引入 `ConcurrentRotatingFileHandler`（`concurrent-log-handler` 包）或外部 logrotate
2. 结构化 JSON：formatter 替换为 `jsonlogger` 或迁移到 `structlog`
3. 集中式：stdout → Loki / ELK（保持 stderr handler 不变即可）
