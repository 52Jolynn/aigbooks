## 10. 警告

### P1 警告（建议修复）

#### P1-1：Book 聚合并发竞态（流程 1）

**位置**：`backend/app/routers/reports.py:54-70`

**问题**：实现为 `SELECT → INSERT/UPDATE` 模式，与实施计划 §3.2 描述的 `INSERT ... ON CONFLICT (isbn) DO UPDATE` 不一致。两个并发请求同 ISBN 时可能均 `SELECT` 返 None，都尝试 `INSERT` → 触发 `UniqueViolation` → 经 `SQLAlchemyError` 处理器返回 `{code:500, msg:"数据库错误"}`。

**建议**：

```python
from sqlalchemy.dialects.postgresql import insert as pg_insert

upsert = (
    pg_insert(Book)
    .values(isbn=isbn, title=title, author=author, cover_path=cover_path)
    .on_conflict_do_update(
        index_elements=[Book.isbn],
        set_={
            "cover_path": cover_path,  # 或 COALESCE
            "updated_at": func.now(),
        },
    )
    .returning(Book.id)
)
book_id = (await db.execute(upsert)).scalar_one()
```

#### P1-2：封面 MIME 校验弱于证据（流程 1）

**位置**：`backend/app/services/storage.py:31-48`

**问题**：`save_cover` 用**文件扩展名**校验（`Path(file.filename).suffix`），而 `save_evidence` 用 `python-magic` 嗅探**真实内容**。两者安全强度不一致：用户上传 `evil.jpg` 实际为可执行文件 → 封面校验通过，证据校验拒绝。

**建议**：`save_cover` 同样使用 `magic.from_buffer(head, mime=True)` 嗅探，对照 `allowed_mime_types` 白名单。

#### P1-3：`RecentReportsOut.total` 语义歧义（流程 2）

**位置**：`backend/app/routers/books.py:37`

**问题**：`total` 字段返回 `len(reports)`（被 LIMIT 截断后的 20），而非 DB 实际总条数。MVP 阶段前端 `Masthead.vue:26` 读 `store.total ?? '—'` 仅用于"Vol. III · No. {reportCount}"展示（语义上展示"已加载的最近条数"也能理解），但若未来加分页/无限滚动会误导。

**建议**：v0.2 改为 `await db.scalar(select(func.count()).select_from(Report))`；或字段改名 `count` 暗示"当前页条数"。
