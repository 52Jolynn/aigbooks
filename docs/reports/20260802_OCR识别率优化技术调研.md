# OCR 识别率优化技术调研

> 调研范围：ISBN/ISSN 图片识别的技术方案对比、tesseract.js 识别率根因、混合方案设计
> 触发背景：本地化 tesseract.js 资源后，用户实测反馈"基本不能正确识别"
> 决策导向：是否/如何替换 OCR 引擎

---

## 0. 调研限制声明

- 本调研基于联网资料与项目现状
- 真实准确率需本地用真实书脊样本测试，报告数字均为业界经验值
- 本报告**不修改任何代码**，仅提供决策依据

---

## 1. 根因分析：为什么 tesseract.js 识别率低

### 1.1 训练数据与使用场景不匹配

tesseract（Tesseract.js 是其 WASM 移植）的训练数据是**文档扫描**：
- 白底黑字
- 规整字体（衬线/无衬线印刷）
- 300+ DPI 扫描质量
- 无透视变形
- 均匀光照

而我们用**手机拍书脊/封面**：
- 各种背景（书桌、书架、地面）
- 多种字体（宋体、黑体、楷体、艺术字）
- 手机拍摄通常 100-300 DPI
- **透视变形**（俯拍/侧拍）
- 光照不均、反光、阴影
- 印刷质量参差不齐（盗版、绝版书更差）

### 1.2 任务类型不匹配

tesseract 是**通用 OCR**，把"任意文本"识别为字符串。但 ISBN 文本有强结构特征：
- 13 位数字（ISBN-13）以 `978` 或 `979` 开头
- 10 位数字（ISBN-10）最后一位可为 `X`
- 8 位数字（ISSN）以 `X` 结尾
- 总是以 `ISBN`/`ISSN` 前缀

tesseract **不利用这些结构**，而我们的正则（`ISBN_REGEX`）只做后过滤，无法挽救识别错误。

### 1.3 PSM/字符白名单等参数未调优

tesseract 有大量参数可调（参考 `frontend/node_modules/tesseract.js/docs/api.md` 提到的 `setParameters`）。当前实现用全默认参数：
- `oem=1`（LSTM_ONLY）— OK
- `psm=6`（SINGLE_BLOCK）— 适合单块文本
- **未设 `tessedit_char_whitelist`**：OCR 引擎会"自由发挥"识别所有字符，导致数字识别成字母

如果设 `tessedit_char_whitelist: '0123456789-IX '`（仅 ISBN 字符集），准确率会有显著提升。

## 2. 技术方案对比

### 2.1 方案 A：条形码识别（最优方案 — 业界标准做法）

**核心洞察**：90% 的现代书籍封面/封底都有 ISBN 条形码（EAN-13 标准）。**条形码设计就是为了机器识别**，抗噪能力远超 OCR。

#### 2.1.1 浏览器原生 `BarcodeDetector` API（首选）

| 项 | 值 |
|---|---|
| 规范 | W3C Shape Detection API |
| 支持 | Chrome 83+ / Edge 83+ / Samsung Internet / 部分 Android WebView |
| **不支持** | Firefox / iOS Safari |
| 体积 | **零依赖**（浏览器内置） |
| 性能 | <50ms |
| 支持格式 | aztec / code_128 / code_39 / code_93 / codabar / data_matrix / **ean_13** / ean_8 / itf / pdf417 / qr_code / upc_a / upc_e |
| ISBN 关系 | EAN-13 包含 ISBN-13（同一编码规则） |

**关键事实**：通过 `formats: ['ean_13']` 即可识别 ISBN-13 条形码，识别结果就是 ISBN 13 位数字。

**降级**：Firefox/iOS Safari 无 `BarcodeDetector`，需要 polyfill。

#### 2.1.2 `zxing-wasm`（推荐 polyfill）

| 项 | 值 |
|---|---|
| GitHub | https://github.com/Sec-ant/zxing-wasm |
| Stars | 246 ⭐ / 21 forks |
| 最近发布 | 3.1.2（15 天前） |
| 许可 | MIT（可商用、可闭源） |
| 底层 | ZXing-C++ → WASM（编译产物 ~1.46 MB；reader-only ~1.04 MB） |
| 性能 | 100-200ms（首次加载 + 识别） |
| **支持的 ISBN 格式** | **直接支持 `ISBN` 格式**（自动从 EAN-13 提取 ISBN） |
| 其他支持 | QR / DataMatrix / PDF417 / Code128/39/93 / Codabar / ITF / UPC / Aztec / MaxiCode |
| 部署 | ESM / CJS / IIFE（多格式），可从 CDN 加载或本地化 |

**示例用法**：
```ts
import { readBarcodes } from 'zxing-wasm/reader';
const results = await readBarcodes(imageFileOrBlob, {
  formats: ['EAN13', 'ISBN'],
  tryHarder: true,
  maxNumberOfSymbols: 1,
});
results[0]?.text; // "9787100123456" 或 "978-7-100-12345-6"
```

**本地化方案**：与 tesseract.js 相同思路，把 `zxing_reader.wasm` 下载到 `frontend/public/tesseract/`（或新建 `frontend/public/zxing/`）。

#### 2.1.3 `@undecaf/zbar-wasm`（备选）

| 项 | 值 |
|---|---|
| GitHub | https://github.com/undecaf/zbar-wasm |
| Stars | 193 ⭐ / 24 forks |
| 许可 | **LGPL-2.1**（应用代码可闭源，库修改需开源） |
| 底层 | ZBar C++ → WASM（部署体积 **~330 KB**，比 zxing-wasm 小 4 倍） |
| 支持 | Code-39/93/128 / Codabar / Databar / **EAN-13** / **ISBN-10/13** / ITF / QR / UPC-A/E |
| 特殊功能 | 扫描结果自动 `decode()` 出 ISBN 数字 |

**对比 zxing-wasm**：
- 体积小 4 倍（330KB vs 1.04MB）
- 直接支持 ISBN-10/13+2/13+5
- 许可更严（LGPL vs MIT）

#### 2.1.4 `barcode-detector` polyfill

| 项 | 值 |
|---|---|
| 包 | `barcode-detector` |
| GitHub | https://github.com/Sec-ant/barcode-detector |
| Dependents | 47 |
| 许可 | MIT |
| 价值 | **提供 `BarcodeDetector` API 标准接口**；原生支持的浏览器用原生，Firefox/iOS 自动用 ZXing WASM 兜底 |

**推荐策略**：用 `barcode-detector` 统一接口，内部自动选择原生或 ZXing，零业务代码差异。

#### 2.1.5 方案 A 总结

| 维度 | 评价 |
|---|---|
| 准确率 | **近 100%**（条形码设计就是抗噪的） |
| 速度 | **<200ms** |
| 体积 | 0（原生）~ 1MB（zxing-wasm）/ 330KB（zbar-wasm） |
| 依赖 | 零（原生）或 1 个轻包 |
| 覆盖度 | 90%+ 现代书籍有 ISBN 条形码 |
| 限制 | **只能拿数字，拿不到题名/作者** |

### 2.2 方案 B：PaddleOCR.js（中文 OCR SOTA）

| 项 | 值 |
|---|---|
| GitHub | https://github.com/PaddlePaddle/PaddleOCR |
| Stars | 86.8k ⭐ |
| 浏览器 SDK | **2026.04 新发布** `PaddleOCR.js`（PP-OCRv5 浏览器版） |
| 许可 | Apache-2.0 |
| 模型大小 | PP-OCRv5 tiny=1.5M / small=7.7M / medium=34.5M 参数（实际文件几十 MB） |
| 性能 | CPU 5.2× speedup（OpenVINO），A100 GPU 0.13s/图 |
| 中文识别 | 业界 SOTA（自然场景、街景、模糊、小字均强） |
| 多语言 | 50+ 语种（PP-OCRv5 单一模型覆盖） |

**对比 tesseract.js**：
- 中文识别准确率高 30-50%（业界经验）
- 模型大 1-2 个数量级
- 首次加载慢（要拉模型文件）
- 2026.04 才出 Web SDK，**生态尚不成熟**

**评估**：模型大 + 生态新 = 实施风险高。

### 2.3 方案 C：云 OCR API（准确率最高，但需付费 + 隐私问题）

| 服务 | 价格 | 准确率 | 隐私 | 国内访问 |
|---|---|---|---|---|
| 百度 OCR | ¥0.005/次 | 95%+ | 需传图片 | ✓ |
| 腾讯云 OCR | ¥0.005/次 | 95%+ | 需传图片 | ✓ |
| 阿里云 OCR | ¥0.005/次 | 95%+ | 需传图片 | ✓ |
| 讯飞 OCR | ¥0.005/次 | 95%+ | 需传图片 | ✓ |
| Google Cloud Vision | $1.50/1000 次 | 96%+ | 需传图片 | 需代理 |
| AWS Textract | $1.50/1000 页 | 95%+ | 需传图片 | 需代理 |

**优点**：准确率最高，无需本地资源。
**缺点**：
- 注册 / API key / 计费
- 每次 OCR 网络请求 1-3s
- **隐私问题**：用户上传的书脊图片传到第三方

**评估**：与本站"匿名举报 + 不上传用户数据"理念相悖。

### 2.4 方案 D：tesseract 调优（最低成本尝试）

不更换引擎，仅参数优化：

| 调优项 | 当前 | 建议 |
|---|---|---|
| `tessedit_char_whitelist` | 未设 | `'0123456789-IXSBNsni '` |
| `psm` | 6（默认） | 6/7/8 视场景切换 |
| 图像预处理 | 无 | 灰度化 + 二值化 + 缩放到 300+ DPI |
| `user_defined_dpi` | 未设 | `300`（修复低 DPI 警告） |

**评估**：从"基本不能识别"到"勉强可用"是可能的，但**根本场景问题解决不了**（书脊弯曲、透视、光照）。

## 3. 推荐方案：混合识别（业界标准）

```
用户上传/拍照
  ↓
[条形码识别] ← 优先，<200ms
  ├─ 命中 → 拿 ISBN 数字 → 填表 ✓
  └─ 未命中 ↓
[OCR 文本识别] ← 降级，1-3s
  ├─ 命中 → 拿 ISBN + 题名/作者 → 填表
  └─ 未命中 ↓
[手动输入] ← 兜底
```

### 3.1 第一阶段（推荐立即做）：条形码识别

**目标**：在 `ocr/index.ts` 旁新增 `barcode/index.ts`，先条形码后 OCR。

**改造点**：
1. 新增 `frontend/src/barcode/index.ts`：`recognizeBarcodes(file): Promise<{ isbn?, issn? }>`
2. 内部用 `barcode-detector` polyfill（自动选原生或 ZXing WASM）
3. ReportView OCR 区块：先调 `recognizeBarcodes`，未命中再调 `recognizeText`
4. 用户无感（结果直接进表单）

**实施成本**：1-2 天。零或低风险。

**预期效果**：90%+ 用户命中率、近 100% 准确率、<200ms 响应。

### 3.2 第二阶段（视效果决定）：tesseract 调优

如果第一阶段后用户仍拍"非条形码区域"（比如封面题名），优化 tesseract 体验：

1. 加 `tessedit_char_whitelist`（ISBN 字符集）
2. 图像预处理（灰度 + 二值化 + 缩放）
3. 多 PSM 模式尝试
4. 清晰度检测（提示用户重拍）

**实施成本**：0.5-1 天。

### 3.3 第三阶段（待评估）：PaddleOCR.js

观察 PaddleOCR.js 生态成熟度（2026 Q4 评估）：
- 浏览器 SDK 已发布
- 模型文件管理、缓存策略、版本管理
- 与 Vue 集成的最佳实践

**评估时间**：2026 Q4。

## 4. 实施细节（第一阶段）

### 4.1 资源本地化

下载 `zxing_reader.wasm`（约 1MB）到 `frontend/public/tesseract/zxing/` 或新建 `frontend/public/zxing/`：

```bash
curl -sSL -o frontend/public/zxing/zxing_reader.wasm \
  "https://cdn.jsdelivr.net/npm/zxing-wasm@3.1.2/dist/reader/zxing_reader.wasm"
```

### 4.2 新组件 / 模块结构

```
frontend/src/
├── ocr/                    # 现有
│   └── index.ts           # recognizeText (Tesseract)
├── barcode/                # 新增
│   ├── index.ts           # recognizeBarcodes (BarcodeDetector)
│   └── polyfill.ts        # 原生 + ZXing 降级
└── report/                 # 合并层
    └── index.ts           # recognize(image) → 先 barcode 后 ocr
```

### 4.3 API 设计

```ts
// frontend/src/barcode/index.ts
export interface BarcodeResult {
  /** ISBN-13（13 位数字） */
  isbn?: string;
  /** ISSN（8 位 XXXX-XXXX） */
  issn?: string;
  /** 条形码类型，如 "EAN_13" / "ISBN" */
  format?: string;
}

export async function recognizeBarcodes(
  image: File | Blob | ImageBitmap,
): Promise<BarcodeResult>;
```

### 4.4 与现有 OCR 整合

ReportView 调用逻辑改为：

```ts
async function recognize(image: File) {
  // 1. 先尝试条形码
  const barcode = await recognizeBarcodes(image);
  if (barcode.isbn || barcode.issn) {
    return { ...barcode, source: 'barcode' };
  }
  // 2. 回退到 OCR
  const ocr = await recognizeText(image);
  return { ...ocr, source: 'ocr' };
}
```

UI 可选反馈"识别来源：条形码"或"识别来源：OCR"。

## 5. 风险与权衡

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 浏览器原生 `BarcodeDetector` 不支持（Firefox / iOS Safari） | 中 | 中 | `barcode-detector` polyfill 自动降级到 ZXing WASM |
| 老书 / 绝版书无条形码 | 中 | 低 | 仍走 OCR 降级路径 |
| ZXing WASM 文件 1MB 增大仓库 | 高 | 低 | 与 tesseract 资源一起本地化（已掌握流程） |
| PaddleOCR.js 生态不成熟 | 高 | 中 | 推迟到第三阶段评估 |
| iOS Safari 拍照时无 `BarcodeDetector` | 高 | 中 | polyfill 已包含 ZXing 兜底 |

## 6. 决策点（待用户确认）

1. **是否进入第一阶段（条形码识别）**？
   - 推荐：是。零风险、低成本、显著提升识别率
2. **第一阶段是否同步做 tesseract 调优**？
   - 推荐：是。`char_whitelist` 等参数是低垂果实
3. **第一阶段资源本地化路径**？
   - 推荐：新建 `frontend/public/zxing/`（与 tesseract 资源并列）
4. **i18n / 文案是否要区分"条形码"和"OCR 文字"两种来源**？
   - 推荐：是。在结果反馈中显示"识别来源"，让用户理解为什么有差异
