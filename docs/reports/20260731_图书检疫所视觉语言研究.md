## 1. 参考原则（提炼自上述领域的共通语言）

下面 7 条原则不是规则，是从公共卫生/档案/编目系统里反复出现的设计本能中提取出来的"动作"——在做 AIGBooks 时可以一一对照。

1. **信息密度服从可读性**：标本签、检疫章、编目卡都把"主体—编号—日期—签发人"四元素摆在最显眼的 1–2 行；其余细节降级成脚注式小字。AIGBooks 的书封、举报、检验记录页面也应如此——别让"故事氛围"压住"事实信息"。
2. **编号即结构**：CDC 标本编号、WHO 报告编号、MARC 字段号都是"看得见"的层级。网站里把"图书 ID / 举报案号 / 检验批号"做成可见编号，比任何装饰都更"检疫所"。
3. **状态靠形状 + 颜色双编码**：GHS 象形图、检疫章、生物危害标志都遵循"颜色 + 几何/字符"双通道。这是 WCAG 1.4.1 要求的"非颜色编码"在专业场景里的标准实践。
4. **留白即洁净**：检验台面、检验报告、编目卡的共同点是"白底 + 极少颜色 + 强排版"。AIGBooks 的"冷白检验环境"应该让用户感觉这是张干净的实验台，而不是设计杂志。
5. **时间戳是信任锚**：检疫记录都会写采样时间、检验时间、签发时间。AIGBooks 的举报、检验结果页要像检验报告一样，让"时间"成为可信任的视觉支点。
6. **签章 = 人格化来源**：检疫章、检验员签名、馆藏章让信息有"出处"。网站里"值班检疫官 / 审核编辑 / 提交人"如果用类似签章的小元素处理，会比头像圆框更贴主题。
7. **慎用情绪色**：实验室/检疫场景里，红/橙永远是"危险或注意"，绿永远是"通过/合格"——这是行业习惯，不是设计偏好。打破这套惯例会立刻显得不专业。

| 档案盒脊背 | 竖排编号 + 短标题 | 抽屉式侧栏导航可借鉴：竖排"案卷号"+"简称" | — |

### 2.3 来自中文编目/排版

- 竖排 + 横排混用：标签区短文字（4–8 字）可考虑竖排，营造"卷宗脊背"感；正文一律横排保证可读性。
- 数字用全角／半角：检验报告里的数字建议半角（与英文 MARC 编号一致），但表头、日期用全角中文标点更"中式档案"。两条规则并存可强化主题。
- 标点不挤压：中文环境下全角逗号、句号前后不应当作英文字符挤紧——但档案排版有时反而要"字字满格"以模仿打字机。两条都可行，要二选一并贯穿。

## 3. 色彩 / 字体 / 布局建议

### 3.1 色彩系统（冷白检验环境）

- **底色**：`#F4F7F5`（冷白偏薄荷）—— 比纯白温和，比米色干净，正是"实验台"的色温。
- **检验绿（合格 / 通过 / 已检疫）**：建议主用 `#0E6B52`（墨绿）。在白底上对比度 6.00，在底色上 6.00，**满足 WCAG AA 正文 4.5:1 与 AAA 大字 4.5:1**，并接近 AAA 正文 7:1 的视觉舒适区。
- **深墨绿（标题 / 重要信息）**：`#0B5D47`，对比度 7.29/7.86，达到 AAA。
- **危险橙（待复检 / 警告 / 注意）**：建议主用 `#A84213`（赤陶橙），白底对比度 5.64/6.08。**避免使用 `#C5541A` 类亮橙**：白底对比度仅 4.18/4.51，**正文不及格**，仅可作大字或描边。
- **拒绝红（不合格 / 危险）**：建议 `#B54708` 起步，深红可选（如 `#8A2A0E`），但要避免与"注意橙"混淆——最好通过**形状**（八边形 vs 圆角矩形）来区分。
- **中性灰阶**：标签用 `#1F2A24` / `#4A5650` / `#8A948E` / `#C4CCC7`，整体偏冷绿调以和绿主色呼应，不要用纯中性灰。
- **物理质感色**（克制使用）：样本袋透明感、文件袋牛皮色可作背景层叠纹理，单页不超过 5% 面积。

**验证方式**：上方对比度数字为离线计算（WCAG 2.x 相对亮度公式）。建议落地前在 Figma / Stark 中再验一次。

### 3.2 状态色 + 形状双编码（WCAG 1.4.1）

| 状态 | 主色 | 形状 / 字符 | 文本前缀 |
|---|---|---|---|
| 合格 / 通过 | `#0E6B52` 绿 | 实心圆 + "✓" | "已检疫" |
| 观察 / 关注 | `#0B5D47` 深绿 | 横线 + "—" | "关注" |
| 待复检 / 警告 | `#A84213` 橙 | 三角 + "!" | "复检中" |
| 不合格 / 危险 | `#8A2A0E` 深红 | 八边形 + "✕" | "退回" |
| 草稿 / 待提交 | `#4A5650` 灰 | 虚线圆 + "…" | "待检" |

——颜色 + 形状 + 文字三冗余。色盲用户也能识别。

### 3.3 字体（中文站点考量）

- **正文**：思源宋体（Noto Serif CJK SC）做"档案/报告"气质，思源黑体（Noto Sans CJK SC）做"屏幕/列表"气质。**避免**：阿里巴巴普惠体、苹方做主字体（太"消费 App"），Inter 做中文（西文气质强、汉字不在体系内）。
- **检验/编号字体**：等宽优先。可考虑 `JetBrains Mono`（开源免费）或 `IBM Plex Mono`。等宽字体是"实验室"的本能语言，用于案号、ID、时间戳、状态标签。
- **显示字（仅用于头图/Hero）**：可考虑 `Source Han Serif Heavy` 或英文 `Tiempos Headline` 之类有"铅字印刷感"的衬线，限于 ≤24pt。
- **字阶**（桌面基准，16px 基础）：
  - 页面 H1：32 / 40（衬线粗体）
  - H2：24 / 32（衬线中粗）
  - H3：20 / 28（无衬线）
  - 正文：16 / 28（无衬线，行高 1.75）
  - 注释 / 元数据：13 / 20（无衬线，颜色降两级）
  - 等宽标签：13 / 20（等宽）
- **中文长正文可读性**：行宽建议 30–38 个汉字（约 640–760px @16px）。低于 28 字会让视线在句中跳回频繁，高于 42 字会丢行。
- **响应式**：
  - 桌面 ≥1024px：多列网格（书封 5–6 列 / 行）。
  - 平板 768–1023px：3–4 列；侧栏折叠为顶部抽屉。
  - 移动 <768px：2 列；"检验记录"改用时间线纵向滚动而非表格。
  - 字号：移动端基础字上调到 17px，避免 iOS 缩放异常。

### 3.4 布局 / 网格

- **基准网格**：8px 原子栅格。书封卡片尺寸按 8 的倍数（推荐 144×216 / 192×288 / 240×360 三档）。
- **留白节奏**：检验报告类页面采用"密—疏—密"——顶部元数据密、正文段间距疏（≥24px）、元数据脚注密。
- **栏数**：长正文 1 栏（≤760px），列表页 12 栏栅格（书封占 2 栏，文字信息占 10 栏）。
- **不要做**：玻璃拟态卡片、紫渐变背景、磨砂模糊、大面积 emoji 装饰、旋转的 3D 书封。

## 4. 动效建议（克制 + 支持 reduced motion）

### 4.1 必备交互
- **书封入场**：列表/详情切换时书封做 200–300ms `opacity` + `translateY(8px)` 的轻位移，**避免** scale/rotate/3D 翻转。
- **检验章落印**：状态变更时"章"从 -8px 透明度 0 落位到 0px 透明度 1，120–180ms 一次 ease-out。
- **举报进度**：用"检验工序"四段式（受理 / 抽检 / 复检 / 归档）水平步骤条，每步切换 200ms 颜色 + 步骤图标激活，**不要用粒子或 loading 圈**。
- **悬浮状态**：书封悬浮时边框 1px 由 `#C4CCC7` → `#0E6B52`，过渡 120ms。

### 4.2 原则
- 总时长：单次交互 ≤300ms；页面切换 ≤400ms；不出现 >500ms 的"开场动画"。
- 缓动：`cubic-bezier(0.2, 0, 0, 1)`（Material standard）或自定 `cubic-bezier(0.16, 1, 0.3, 1)`，避免 `linear` 与 `ease-in-out` 的"弹跳感"。
- 路径动画：禁用。`top/left/margin` 改用 `transform/opacity`（避免 layout thrash）。
- 滚动联动：使用 `IntersectionObserver`，不要监听 scroll 事件。

### 4.3 动效与 a11y
- 全局 `prefers-reduced-motion: reduce` 媒体查询：所有动效降级为 ≤80ms 的 `opacity` 渐显，禁用 `transform`。
- 避免"持续运动"（旋转 loader 改静态文字"加载中…"）。
- 焦点环始终可见，**不要**用"动效焦点"代替视觉焦点。

## 5. 不可照搬项（避雷清单）

| 类别 | 不能照搬 | 原因 |
|---|---|---|
| 视觉风格 | 紫色渐变 / 玻璃拟态 / 弥散光斑 / 磨砂模糊 / 大色块 | 已是 2023–2025 的"AI 默认美学"，与"专业审慎"目标冲突 |
| 视觉风格 | 深色模式（v1 不上）+ 暗色 Hero 大背景图 | "检验环境"语义上是"明亮操作台"，强上深色会失真 |
| 视觉风格 | 仿宋雕版、毛笔字、朱红印章大面积铺底 | 容易滑向"古籍/中医/风水"刻板印象，与"科学检验"对冲 |
| 视觉风格 | 荧光绿 / 霓虹色 / Y2K 渐变 | 与"实验室冷白"气质相反 |
| 视觉风格 | 拟物化"3D 书封"+ 厚阴影 + 倾斜 | 与"标本贴标签"的扁平档案感冲突 |
| 交互 | 启动动画 / Splash 视频 / 大型 Lottie | 浪费用户等待，专业站点不该有 |
| 交互 | 自动播放音频、滚动视差、鼠标跟随特效 | 与"审慎"调性冲突；也违反 reduced motion |
| 内容 | 直接引用 WHO / CDC / 国家市场监管总局的徽章原图 | 法律风险；且会让用户误以为是官方背书 |

| 内容 | 用 GHS 象形图原图标（骷髅/腐蚀/火焰） | 这些图标在 UN GHS / OSHA 监管下使用，擅自使用会引误解 |
| 字体 | Inter / Roboto / 苹方（PingFang）作为主字体 | 已被中文互联网泛用，缺乏"档案感" |
| 配色 | 把"危险橙"做成荧光橙或糖果橘 | 失去"危险"的专业语义，滑向消费 App |
| 排版 | 中英混排不预留间距 / 中文标点全角半角混用 | 长期阅读会显著降低舒适度 |

## 6. 推荐方向

### 6.1 核心记忆点（一句话 + 落地）

> **"让每一本书看起来都像一张刚被贴上标签的样本。"**

具体落地：
- **书封 = 样本卡**：默认显示书封 + 右上角一个"检验状态章"（圆形/八边形，盖在封面上），章上有案号 + 日期。
- **举报 = 检验工单**：用 MARC 字段名（"245 题名 / 020 ISBN / 650 主题"）作填写区小标签，而不是"标题 / 内容"。
- **检验结果 = 报告单**：固定四段：① 样本描述 ② 检验方法（抽检类型） ③ 结果（含章） ④ 签发人 + 时间。
- **档案袋肌理**：背景层允许使用极淡的牛皮纸纹理（≤5% 面积，2% 不透明度），所有书封所在的"检验台面"用冷白底色保持洁净。
- **等宽编号**贯穿：所有 ID / 时间戳 / 状态码用等宽字体，是最便宜也最有效的"实验室"记忆点。

### 6.2 风格关键词（设计交付时贴在 Brief 顶部）

```
冷白实验台 / 档案抽屉 / 检验章 / 等宽编号 / 标本标签 /
克制动效 / 双编码状态 / 留白即洁净
```

### 6.3 一句话方向总结

> 形态像一份新印好的检验报告：底色冷白、字色深墨、点缀检验绿与危险橙；书封是被贴上标签的样本；编号贯穿始终；动效只在"落章"那一瞬；色盲用户用形状也能读懂状态。

### 6.4 落地前要先做的事

1. 用 Figma / Stark 把 3.1 的色彩与建议正文色重新跑一遍对比度。
2. 把"案号格式 `AIG-YYYYMMDD-NNNN`"和"检验章四状态"作为组件名锁定，写入设计 token。
3. 选 1–2 本代表性的虚构书，**先做"检验报告"风格的详情页单图**，再决定是否扩展到列表/首页。
4. 准备 1 张 reduced-motion 截图和 1 张正常动效截图，作为"动效克制的对照证"放进设计说明。

## 8. 给"实施计划"的对接建议

- 本研究只确定**视觉语言**，不写组件清单、不写代码、不动设计 token 文件。
- 建议下一步：先开一个 30 分钟的设计 Brief 对齐会，决策下列 4 个点，再进入设计稿与实现：
  1. 检验绿、危险橙的具体十六进制是否采纳本研究建议值。
  2. 案号格式是否锁定为 `AIG-YYYYMMDD-NNNN`。
  3. 是否启用"等宽编号"作为全站记忆点（涉及 token 命名）。
  4. v1 是否同时交付 light / dark 主题（本研究建议 v1 只做 light）。
- 决策后由"实施计划"环节负责落 design token、组件库结构、Storybook 文档。
